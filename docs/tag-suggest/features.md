# 태그 자동 추천 — 기능 소개

> 대상: 팀 레포 PR log-dev-club/loghub#20 (브랜치 `claude/serene-meitner-g9bnh0`, `d4a06e3`) · 작성일 2026-11-20 · 갱신 2026-11-23

## 한 줄 요약

글을 쓸 때 **"태그 추천" 버튼**을 누르면, 관리자가 등록해 둔 **태그 목록 안에서** 제목·본문에 맞는 태그를 최대 5개 추천한다.
추천은 칩으로 보여 주고, 사용자가 칩을 눌러야 태그로 들어간다 (자동으로 붙이지 않는다).

## 진행 단계

| 단계 | 상태 | 내용 |
| --- | --- | --- |
| 1. 태그 목록 관리 | 완료 | 관리자가 추천 후보 태그와 동의어를 관리. 게시물에 쓴 새 태그는 목록에 자동 추가 |
| 1-1. 태그 저장 규칙 | 완료 | 저장할 때 태그를 정규화하고, 동의어는 대표 태그로 바꿈 |
| 2. 키워드 매칭 추천 | 완료 | 태그 이름·동의어가 글에 나온 횟수로 추천 |
| 3. Jev AI 시험 | 도구 완료, 실제 시험 대기 | 샘플 글로 키워드 매칭과 Jev 를 비교하는 로컬 도구 (`tools/jev-eval`). 유효한 API 키가 없어 실제 비교는 아직 못 함 |
| 4. Jev 연동 | 시작 전 | 3단계 결과가 키워드 매칭보다 확실히 나을 때만 진행 |

## 1. 태그 목록 관리 (관리자)

관리자 화면(`/admin`) 아래에 **태그 목록** 영역이 생겼다. 관리자·최고 관리자만 볼 수 있다.

- **추가**: 태그 이름, 설명(선택), 동의어(쉼표로 구분)를 입력한다.
  - 예: 이름 `react`, 설명 `React UI 라이브러리`, 동의어 `jsx, usestate, 리액트`
- **수정·삭제**: 목록에서 바로 고친다. 동의어는 저장할 때 통째로 바뀐다.
  - 목록에서 지워도 **이미 게시물에 붙은 태그는 그대로** 남는다. 이 목록은 "추천 후보"일 뿐, 게시물 태그와 연결되지 않는다.
- **자동 추가**: 게시물을 쓰거나 고칠 때 목록에 없는 새 태그는 목록에 자동으로 추가된다(설명·동의어 없이). 관리자가 나중에 설명·동의어를 붙이거나 지우면 된다.
  - 다른 태그의 동의어로 등록된 이름(예: `리액트`)은 따로 추가하지 않는다.
  - 기존 게시물에 쓰인 태그는 마이그레이션이 한 번 목록에 담는다.
- **후보 표시**: 게시물에서 쓰이고 있지만 목록에 없는 태그를 칩으로 보여 준다. 누르면 추가 폼의 이름 칸에 채워진다.
- **정리 규칙**: 이름과 동의어는 앞뒤 공백·맨 앞 `#` 를 지우고 소문자로 저장한다. 이름은 50자, 설명은 200자, 동의어는 태그당 30개까지.

### `기타` 태그

짧은 글·일상 글·공지용으로 `기타` 를 목록에 넣어 두었다 (샘플 목록과 로컬 DB).

| 이름 | 설명 | 동의어 |
| --- | --- | --- |
| 기타 | 짧은 글, 일상 글, 공지 | 일상, 잡담, 공지, 일정, 근황, 스터디, 모임 |

- 서버에 특별한 처리는 없다. **다른 태그와 똑같이 동의어가 글에 나오면 추천**된다.
- 그래서 동의어가 하나도 없는 짧은 글(예: "오늘 점심 / 산책했다")에는 추천되지 않는다. 이럴 때는 사용자가 직접 입력한다.
- 동의어는 관리자 화면에서 언제든 늘릴 수 있다.

## 2. 글쓰기 화면 태그 추천 (사용자)

1. 제목이나 본문을 입력하면 태그 입력란 옆의 **태그 추천** 버튼이 켜진다.
2. 버튼을 누르면 `+ react`, `+ svelte` 같은 칩이 나온다. 추천할 게 없으면 "추천할 태그가 없습니다" 가 뜬다.
3. 칩을 누르면 태그 입력란에 추가되고 그 칩은 사라진다.

추천 규칙:

- 관리자가 등록한 목록 안에서만 고른다. 목록이 비어 있으면 항상 "추천할 태그가 없습니다".
- 태그 이름이나 동의어가 **제목에 나오면 3점, 본문에 나오면 1점**. 점수 높은 순으로 최대 5개.
- 영어·숫자 키워드는 단어 단위로 찾는다 (`go` 가 `google` 에 걸리지 않음). 한글 키워드는 조사가 붙어도 찾는다 (`리액트를`).
- 본문의 **코드 블록, 이미지, URL 은 무시**하고 앞 2,000자만 본다.
- 이미 입력한 태그는 추천하지 않는다.
- 로그인한 사용자만 쓸 수 있다. 외부 서비스를 부르지 않는다.

## 3. 게시물 태그 저장 규칙

글을 쓰거나 고칠 때 태그는 아래 순서로 정리된 뒤 저장된다.

1. **정규화**: 앞뒤 공백과 맨 앞 `#` 를 지우고 소문자로 바꾼다. 빈 값과 중복은 뺀다.
   - 글쓰기 화면에서도 태그 입력란을 벗어나면 같은 규칙으로 바꿔 보여 준다.
   - 예: `#React, 리액트, Golang, react` → `react, 리액트, golang`
2. **동의어 → 대표 태그**: 태그 목록에 동의어로 등록된 태그를 대표 태그 이름으로 바꾸고, 바꾼 뒤 생긴 중복은 하나로 합친다.
   - 예: `리액트` → `react`, `golang` → `go`, `스터디` → `기타`
   - 그 이름 자체가 목록의 태그이면 바꾸지 않는다 (태그 이름이 우선).
   - 같은 동의어가 둘 이상의 태그에 등록돼 있으면, 어느 쪽인지 정할 수 없으므로 바꾸지 않는다.
3. **목록에 자동 추가**: 결과 태그 중 목록에 없는 것을 목록에 추가한다.

기존 게시물에도 같은 규칙을 한 번 적용한다. 마이그레이션이 동의어 태그를 대표 태그로 바꾸고, 한 글 안에서 겹치면 합친다.
이 마이그레이션 뒤에 새로 등록한 동의어는 **그 뒤에 저장되는 글부터** 적용된다.

## 4. Jev AI 시험 도구 (개발자용)

`tools/jev-eval/eval.mjs` 는 앱 기능이 아니라 **비교 시험 도구**다. 실제 서비스에는 영향이 없다.

- `node eval.mjs seed`: 샘플 태그 15개를 로컬 DB 에 등록한다.
- `node eval.mjs run`: 샘플 글 12개를 키워드 매칭과 Jev 로 각각 추천하고, 정답과 비교한 리포트를 `results/` 에 남긴다 (커밋되지 않음).
- 실제 팀 게시물은 Jev 로 보내지 않는다. 외부 전송에 대한 팀 동의가 아직 없다.
- Jev 키는 환경 변수 `JEV_API_KEY` 로만 넘긴다.

### Jev 공식 문서에서 확인한 내용

| 항목 | 내용 | 출처 |
| --- | --- | --- |
| 엔드포인트·인증 | `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <키>` | https://docs.typesafe.ai/api/system-one |
| 모델 | 본문 `model` 필드. 별칭 `jev-latest`, 고정 ID `jev-1.14.0` | https://docs.typesafe.ai/models |
| 다중 라벨 | 지원 안 함 (Choice 는 하나만 고름). 대신 질문 여러 개를 한 요청에 넣을 수 있음 | https://docs.typesafe.ai/primitives |
| 제한 | 질문 수 제한 없음. 요청 전체 64k 토큰, state + 질문 하나 32k 토큰 | https://docs.typesafe.ai/models |
| 가격 | 입력 100만 토큰당 $0.042, 출력 무료 | https://docs.typesafe.ai/models |
| 학습 사용 | 입력으로 학습하지 않는다고 명시 | https://typesafe.ai/legal/privacy-policy |
| 보관 | 기간 명시 없음. 보관하지 않는 옵션(ZDR)은 엔터프라이즈 전용 | https://typesafe.ai/legal/data-processing |

## 팀원이 할 일 (팀 레포에 올라간 뒤)

- `git pull` 후 **api 서버만 재시작**하면 된다. 새 마이그레이션 3개는 기동할 때 자동 적용된다.
  - 기존 게시물의 태그가 목록에 담기고, 동의어 태그는 대표 태그로 바뀐다(마이그레이션 시점의 목록 기준).
  - 새로 추가된 `api/build.rs` 덕분에, 앞으로는 마이그레이션 SQL 만 추가돼도 `cargo run` 때 다시 빌드된다.
- 의존성(`Cargo.toml`, `package.json`)과 `.env.example` 은 바뀌지 않았다. `npm install`·새 환경 변수는 필요 없다.
- 추천을 쓰려면 관리자가 `/admin` 에서 태그를 등록해야 한다. 로컬에서는 `cd tools/jev-eval && node eval.mjs seed` 로 샘플 태그를 넣을 수 있다.

## 알려진 한계

- 키워드 매칭은 문맥을 모른다.
  - "React 대신 Svelte" 글에 `react` 를 추천한다.
  - 단어로 나오지 않는 주제(예: 성능 개선 글의 `performance`)는 놓친다.
- 동의어가 없는 짧은 글에는 아무 태그도 추천하지 않는다.
- 게시물에 쓴 새 태그가 목록에 자동으로 쌓이므로, 오타 태그도 목록에 들어간다. 관리자가 가끔 정리해야 한다.
- 동의어 변환은 저장할 때만 일어난다. 동의어를 새로 등록해도 이미 저장된 글은 바뀌지 않는다.
- Jev 가 실제로 이 한계를 넘는지는 아직 확인하지 못했다.
